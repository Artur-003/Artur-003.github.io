Identity and security tokens

Created a local training account and SOC analyst group, inspected their SIDs and compared standard and elevated security tokens.

  • A SID identifies a security principal such as a user or group.
  • Group membership contributes permissions to the access token.
  • UAC normally gives an administrator a medium-integrity token and requests consent before creating a high-integrity process.
  • Privileges and object permissions are related but different: privileges grant system-wide capabilities, while ACLs govern access to specific securable objects.

NTFS permissions

Built a protected C:\SOC-Lab directory, disabled inherited permissions and assigned explicit rights to SYSTEM, Administrators and a dedicated analyst group.

Persistence surfaces

Reviewed common locations that may contain legitimate configuration or attacker persistence:

  • HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  • HKLM\Software\Microsoft\Windows\CurrentVersion\Run
  • Windows services and their executable paths
  • Scheduled tasks, triggers, principals and actions

The presence of an entry is not automatically malicious. The analyst validates path, signature, parent process, user context, creation time and related telemetry.
