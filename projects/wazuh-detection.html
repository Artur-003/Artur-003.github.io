Wazuh Detection Lab

Correlating Windows endpoint telemetry to identify account creation, suspicious PowerShell activity and repeated authentication failures in a controlled environment.

WazuhSysmonWindows SecurityPowerShellMITRE ATT&CK

Objective

Build a repeatable analyst workflow: generate known activity, collect independent telemetry sources, correlate related events, determine whether the behaviour is suspicious and record the detection opportunity.

Safety: all activity was performed inside an isolated home laboratory against systems I own and control.

Test scenarios

1. Local account creation

A local account was created to validate visibility into account-management activity. The investigation connected the command-line process with the resulting Windows audit event.

A controlled PowerShell command produced script-block, process and network telemetry. Wazuh generated a high-severity alert associated with transfer and command-execution techniques.

3. Repeated failed logons

Failed authentication events were reviewed as a sequence rather than isolated records. The analyst pivoted on account, source, logon type and the number of attempts within a time window.

EventKey fieldsQuestion answered
4625Target account, source address, logon type, statusWho attempted access, from where, how and why did it fail?

Analyst workflow

  1. Fix the event time and host before pivoting.
  2. Identify the initiating user and process.
  3. Review the full command line and parent-child relationship.
  4. Correlate network, authentication and file events in the same time window.
  5. Map the observed behaviour to ATT&CK only after validating the evidence.
  6. Record the verdict, confidence, scope and recommended response.

Result

3controlled scenarios correlated
4independent telemetry sources used
2ATT&CK techniques validated

The lab demonstrated that an alert alone is not a conclusion. A defensible verdict requires endpoint context, event sequencing and confirmation across multiple telemetry sources.

Lessons learned

  • Script Block Logging reveals PowerShell intent that process-name-only detection may miss.
  • Process GUID is more reliable than PID for correlation because operating systems can reuse PIDs.
  • A single failed logon is weak evidence; frequency, source, account and surrounding activity determine severity.
  • Detection quality improves when the rule contains enough context for a junior analyst to triage it quickly.
